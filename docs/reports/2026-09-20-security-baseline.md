## 3. 결정 필요

**① 커밋 이메일** — 지금 로컬 커밋 작성자는 개인 Gmail이고, 머지 커밋은 GitHub noreply다. 앞으로를 noreply로 바꾸려면:
```bash
git config --global user.email "59680837+dataCake-MSK@users.noreply.github.com"
```
GitHub → Settings → Emails에서 "Keep my email addresses private"와 "Block command line pushes that expose my email"도 함께 켜는 것을 권한다. **과거 커밋까지 바꾸려면 기록 재작성이 필요**하므로 따로 결정한다.

**② main 브랜치 보호** — 공개 저장소는 무료로 ruleset을 쓸 수 있다. "PR 없이는 main에 push 금지"만 켜면 지금 작업 방식과 충돌하지 않는다. 리뷰 승인 필수까지 켜면 1인 개발에서는 🟢 자체 머지가 막힌다.

**③ CI 보안 단계(이슈 #3에 포함)** — gitleaks(비밀 값 스캔), `npm audit`·`uv pip audit`(의존성), CodeQL(공개 저장소 무료 정적 분석). 실행 시간이 늘어난다.

## 4. 프로젝트 전반 보안 기준 (모든 이슈에 적용)

| 영역 | 기준 | 확인 방법 |
|---|---|---|
| 인증 | 비밀번호 Argon2, JWT는 `JWT_SECRET`(없으면 시작 실패), access 15분·refresh 14일, 토큰 `type` 구분 | SRS-010~012 AC |
| 인가 | 유저 소유 리소스는 `user_id` 필터 필수, 남의 것은 404, 역할 부족은 403, 공용 데이터 변경은 admin만 | 이슈마다 "다른 유저 토큰 → 404" 테스트 |
| 입력 검증 | Pydantic 스키마로 타입·길이 제한, 정렬·필터 파라미터는 허용 목록 | 422 테스트 |
| 출력 | 오류 메시지에 내부 정보·존재 여부를 흘리지 않음(로그인 실패는 같은 문구) | SRS-011 AC |
| SQL | ORM만 사용, 문자열로 만든 raw SQL 금지 | 코드 리뷰 |
| 비밀 값 | `.env`에서만 읽기, `.env.example`엔 이름만, 로그·오류·일지에 출력 금지 | Stop 훅 스캔 + commit 스킬 |
| 의존성 | `uv.lock`·`package-lock.json` 커밋, Dependabot 알림 처리, 새 패키지는 PR에서 이유 설명 | 🟡 등급으로 사용자 확인 |
| 앱(Expo) | 토큰은 `expo-secure-store`, `EXPO_PUBLIC_*`에는 비밀 값 금지(번들에 그대로 들어감) | SRS-013 |
| 개발 서버·터널 | 터널이 켜진 동안 로컬 API가 인터넷에 공개됨 → 확인 끝나면 즉시 종료, 실데이터 없는 상태에서만 사용 | CLAUDE.md 서버 관리 규칙 |
| 요청 제한 | 공개 엔드포인트 `PUBLIC_RATE_LIMIT`, 인증 엔드포인트 `AUTH_RATE_LIMIT` | 이슈 #9 테스트 |
| CORS | 허용 출처는 환경 변수로 명시, 와일드카드 금지, 쿠키를 쓰지 않으므로 `allow_credentials=False` | 이슈 #9 테스트 |
| 배포(추후) | HTTPS 강제, `/docs` 공개 여부 재검토, 서버 로그에 토큰·비밀번호 남기지 않기 | 배포 이슈에서 |

## 5. 이번에 넣은 자동 조치
1. **Dependabot 알림 + 보안 업데이트**: 취약한 의존성이 생기면 GitHub가 알리고 PR을 만든다.
2. **Stop 훅 비밀 값 스캔**(`.claude/hooks/stop-vcs-check.js`): 턴을 끝내기 전에 작업 트리에서 키·토큰·DB 접속 문자열·개인 터널 주소 패턴을 찾으면 종료를 막고 알린다. 커밋 전에 걸러진다.
3. **CLAUDE.md 보안 점검 항목**: 이슈를 끝낼 때마다 위 4절 기준을 확인하도록 규칙에 명시.
4. **PR 템플릿**: 비밀 값·인가·의존성 체크 항목.

## 6. 유출이 의심될 때 (순서)

## 7. 사고 시나리오와 발생 가능한 문제 상황 (위험 순)

현재 상태 기준: 인증 없음, DB 없음, 실제 사용자 데이터 없음, 공개 저장소, 로컬 개발 + 터널.
**위험 = 가능성 × 영향**으로 매겼고, "미도래"는 해당 이슈를 시작하면 바로 올라간다는 뜻이다.

### 높음

#### S1. 비밀 값을 커밋해 공개 노출 — 가능성 중 · 영향 높음
곧 `JWT_SECRET`과 DB 비밀번호가 생긴다. 공개 저장소는 자동 스캐너가 상시 훑는다.
1. **정보 탈취** — DB 접속 정보로 개발 DB의 계정·학습 기록 전체 조회
2. **위조 로그인** — `JWT_SECRET`을 알면 아무 user_id로도 유효한 토큰을 만들어 admin 행세 가능
3. **되돌릴 수 없음** — 커밋을 지워도 포크·캐시·스캐너 수집본에 남음 → 키 폐기가 유일한 복구
4. **계정 도용 확산** — 다른 서비스와 같은 비밀번호를 썼다면 그쪽까지 번짐
- 방어: push protection, `.env` 무시, commit 스킬 패턴 점검, Stop 훅 스캔 / 구멍: 훅 패턴 밖의 형태, CI 스캔 없음

#### S2. 터널을 켜둔 채 방치 — 가능성 중 · 영향 지금 낮음 → 인증·DB 이후 높음
`cloudflared`가 켜져 있으면 PC의 8000 포트가 인터넷에 열린다. 주소는 무작위지만 비밀이 아니다.
1. **무인증 API 호출** — 인증이 붙기 전 단계에서는 누구나 데이터 생성·조회 가능
2. **개발 DB 노출** — DB 연결 후에는 API를 통해 전체 데이터 열람·변조
3. **자원 소모·요금** — 무한 요청으로 PC 자원 소진(현재 rate limit이 일부 완화)
4. **내부망 발판** — 실수로 다른 포트(DB 5432 등)를 터널링하면 PC 자체가 공격 대상
- 방어: 30분 확인 규칙, 확인 후 즉시 종료, 포트 점검 보고 / 구멍: 사람이 깜빡하면 그대로

#### S3. 인가 누락(IDOR) — 가능성 중 · 영향 높음 · 미도래(이슈 #14부터)
쿼리에서 `user_id` 조건을 한 번 빠뜨리면 생긴다.
1. **타인 학습 기록 조회** — 남의 `word_stats`·퀴즈 세션이 그대로 응답에 포함
2. **타인 데이터 변조·삭제** — 남의 즐겨찾기·커스텀 단어를 수정하거나 지움
3. **존재 노출** — 403으로 응답하면 ID를 훑어 "몇 명이 있는지"까지 파악 가능
4. **조용한 실패** — 1인 사용 중에는 아무도 눈치채지 못하고 배포까지 감
- 방어: Repository에서 `user_id` 필수(이슈 #15), 404 응답 규칙, 이슈마다 "다른 유저 토큰 → 404" 테스트

### 중간

#### S4. 인증 구현 자체의 결함 — 가능성 중 · 영향 높음 · 미도래(이슈 #5~#7)
1. **토큰 위조** — 서명 검증을 빠뜨리거나 `alg=none`을 허용하면 아무나 로그인
2. **만료 무시** — `exp` 검증 누락 시 옛 토큰이 영원히 유효
3. **권한 상승** — access/refresh 구분(`type`)을 안 하면 refresh로 API 전체 사용
4. **비밀번호 유출** — 해싱 실수(평문·약한 해시)로 DB 유출 시 원문 복원
5. **계정 열거** — "없는 이메일"과 "틀린 비밀번호" 응답이 다르면 가입자 목록 추정
- 방어: ADR-0004(Argon2, PyJWT, type 구분, secret 없으면 시작 실패) + 위조·만료 토큰 테스트를 AC에 포함

#### S5. 개발 PC가 공급망 공격에 당함 — 가능성 낮음~중 · 영향 매우 높음
악성 패키지·템플릿 설정이 설치/빌드 시점에 내 PC에서 실행된다.
1. **개발자 자격증명 탈취** — `gh` 토큰, SSH 키, `.env`, 브라우저 세션
2. **저장소 오염** — 탈취한 토큰으로 악성 커밋 push, 릴리스 조작
3. **지속성 확보** — 설치 스크립트가 백도어를 남김
4. **다른 프로젝트 감염** — 같은 PC의 다른 저장소·계정까지 번짐
- 실제 사례(이 프로젝트): Expo 템플릿이 `mobile/.claude/settings.json`으로 플러그인을 자동 활성화하려 함 → 제거
- 방어: 새 의존성은 🟡로 사용자 확인 + **8절 판단 기준**, lock 파일 커밋, 생성물 검토

#### S6. 알려진 취약 의존성 누적 — 가능성 높음(지속) · 영향 낮음~중
1. **간접 의존성의 취약점** — 2026-09-20 `uuid` moderate 1건 실제 발생(직접 사용 안 해 영향 낮음)
2. **런타임 취약점** — 파싱·직렬화 라이브러리 결함이 원격 공격으로 이어질 수 있음
3. **방치 누적** — 업데이트를 미루면 한 번에 큰 버전 점프가 필요해져 더 미루게 됨
- 방어: Dependabot 알림 + 보안 업데이트 PR(활성화됨)

### 낮음

#### S7. 공개 저장소에 남는 개인 정보 — 가능성 확실(이미 노출) · 영향 낮음
1. **이메일 수집** — 커밋 작성자의 개인 Gmail이 공개 기록에 남음 → 스팸·피싱 표적
2. **생활 정보 추정** — 커밋 시각 패턴, 일지 내용으로 생활 리듬·위치 추정
3. **내부 주소 노출** — 실수로 남긴 LAN IP·터널 주소가 기록에 남음
- 방어: 문서에 개인 URL·IP 금지 규칙, Stop 훅 스캔 / 미적용: noreply 이메일(3절 결정 ①, 보류)

#### S8. 규칙 우회로 main 오염 — 가능성 낮음 · 영향 중
1. **검토 없는 변경** — 브랜치 보호가 없어 기술적으로 main 직접 push가 가능
2. **되돌리기 비용** — 잘못 들어가도 기록이 남아 복구는 가능하지만 이력이 지저분해짐
- 방어: CLAUDE.md 금지 규칙 + Stop 훅 경고 / 미적용: 브랜치 보호(3절 결정 ②, 보류)

#### S9. rate limit 우회·오탐 — 가능성 중 · 영향 낮음
1. **우회** — IP를 바꾸면 제한을 피할 수 있음(무차별 대입을 늦출 뿐 막지 못함)
2. **오탐** — 공유기·프록시 뒤 여러 사용자가 한 IP로 묶여 정상 요청이 429
3. **카운터 분산** — 메모리 저장이라 서버를 여러 대로 늘리면 제한이 사실상 N배
- 방어: 인증에 강한 비밀번호 규칙 병행, 배포 시 저장소를 Redis로 교체 검토

#### S10. 앱 번들에 담긴 값 노출 — 가능성 확실 · 영향 낮음
1. **설정 노출** — `EXPO_PUBLIC_*`는 앱 안에 평문으로 들어가 누구나 추출 가능
2. **API 주소 파악** — 백엔드 주소가 드러나 직접 호출 시도 가능(인증으로 방어해야 함)
- 방어: `EXPO_PUBLIC_*`에는 비밀 값 금지, 토큰은 `expo-secure-store`

## 8. 신규 의존성 판단 기준 (Claude가 적용)

새 패키지를 제안하기 전에 아래를 확인하고, **결과를 PR 본문에 2~3줄로 적는다**. 사용자는 이 요약만 보고 판단할 수 있어야 한다.

### 먼저 묻는 것
1. **없어도 되는가?** 표준 라이브러리나 이미 있는 패키지(FastAPI·Pydantic·SQLAlchemy 등)로 10~30줄 안에 되면 추가하지 않는다.
2. **공식 문서가 권하는가?** FastAPI·Expo 공식 문서가 예제로 쓰는 것을 1순위로 한다(예: PyJWT, pwdlib, slowapi).

### 확인 항목 (하나라도 걸리면 사용자에게 알리고 대안을 함께 제시)
| 항목 | 괜찮음 | 꺼림칙함 |
|---|---|---|
| 관리 상태 | 최근 12개월 내 릴리스, 이슈에 응답 | 2년 이상 방치, 아카이브됨 |
| 사용 규모 | 주간 다운로드 수만 이상, 널리 쓰이는 프로젝트가 의존 | 다운로드 수백 이하, 사례 없음 |
| 배포자 | 조직·알려진 메인테이너, 저장소와 패키지명이 일치 | 계정 만든 지 얼마 안 됨, 저장소 링크 없음/불일치 |
| 이름 | 공식 문서에 적힌 정확한 이름 | 유명 패키지와 한 글자 차이(타이포스쿼팅) |
| 크기 | 의존성 몇 개 수준 | 간접 의존성이 수십 개씩 딸려옴 |
| 설치 동작 | 순수 파이썬/JS | `postinstall` 스크립트, 설치 중 네트워크 접근, 바이너리 다운로드 |
| 권한 요구 | 없음 | 토큰·자격증명·환경 전체 접근을 요구 |
| 라이선스 | MIT·Apache-2.0·BSD | 카피레프트(GPL 계열)나 라이선스 불명 |
| 보안 이력 | 알려진 취약점 없음 또는 패치됨 | 미패치 취약점, 과거 탈취 사고 이력 |

### 하지 않는 것
- 설치 스크립트가 있는 패키지를 **확인 없이** 설치하지 않는다.
- 문제를 해결하려고 **처음 보는 패키지를 즉흥적으로** 추가하지 않는다. 먼저 공식 문서를 찾는다.
- 버전을 `*`나 `latest`로 두지 않는다. lock 파일(`uv.lock`, `package-lock.json`)을 반드시 커밋한다.
- 같은 일을 하는 패키지를 중복으로 넣지 않는다.

### PR에 적을 형식
```
새 의존성: slowapi 0.1.10 (MIT)
- 왜: FastAPI용 요청 제한. 직접 구현하면 저장소·윈도우 계산을 새로 만들어야 함
- 상태: 2026-06 릴리스, 메모리 저장소 지원, 간접 의존성 2개(limits, wrapt)
- 대안: 직접 구현(유지보수 부담), fastapi-limiter(Redis 필요)
```

## 9. CI 보안 도구 3종 (3절 결정 ③ 참고)

지금은 도입을 보류했다. 이슈 #4(DB)·#5(인증) 착수 전에 다시 검토한다.

| 도구 | 무엇을 하나 | 무엇을 못 잡나 | 비용 | 권장 시점 |
|---|---|---|---|---|
| **gitleaks** | 커밋·기록·파일에서 **비밀 값 패턴**(API 키, 토큰, 개인 키)을 찾는 오픈소스 스캐너. GitHub Action으로 PR마다 실행 | 패턴에 없는 형태의 비밀 값, 이미 유출된 키의 폐기 | 무료(MIT). Action은 **개인 계정 무료**, 조직은 무료 라이선스 키 필요 | S1 대비. 이슈 #4 전 |
| **의존성 감사** | 설치된 패키지 목록을 취약점 DB와 대조. JS는 `npm audit`, Python은 `pip-audit`(PyPA, Python Packaging Advisory DB·OSV 사용). GitHub의 Dependabot은 저장소에서 같은 일을 상시 수행 | 아직 공개되지 않은 취약점, 악성 패키지 자체(=공급망) | 무료 | S6 대비. Dependabot은 **이미 켬**, CI 추가는 선택 |
| **CodeQL** | GitHub의 **코드 정적 분석**. 코드를 DB로 만들어 질의해 SQL 인젝션·인가 누락·위험한 흐름 같은 패턴을 찾는다. Python·JS/TS 지원 | 비즈니스 로직 오류, 설정 실수, 런타임 문제 | 공개 저장소는 기본 설정 사용 가능(Actions 필요) | S3·S4 대비. 인증·DB 코드가 생긴 뒤가 효과적 |

- 셋은 겹치지 않는다: **gitleaks = 비밀 값**, **의존성 감사 = 남의 코드의 알려진 취약점**, **CodeQL = 내 코드의 취약한 패턴**.
- 도입한다면 순서는 gitleaks → 의존성 감사 → CodeQL. 앞의 둘은 빠르고, CodeQL은 실행 시간이 길다.

## 갱신 (2026-09-20)
- 3절 결정 ①(noreply 이메일) ②(브랜치 보호) ③(CI 보안 도구)은 **일단 보류**하기로 했다. S1·S7·S8의 "미적용" 항목이 여기에 해당한다.
- Dependabot 첫 경고 발생: `mobile/package-lock.json`의 `uuid`(moderate, `< 11.1.1`, Expo의 간접 의존성). 직접 사용하지 않아 영향은 낮고, 의존성 변경이므로 별도 PR(🟡)로 처리한다.
- 7·8·9절을 추가했다(사고 시나리오별 문제 상황, 신규 의존성 판단 기준, CI 도구 설명).
