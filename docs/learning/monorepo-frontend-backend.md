# 프론트엔드·백엔드를 한 저장소에서(모노레포) vs 분리

## 핵심 개념
- **모노레포**: 한 저장소 안에 여러 프로그램을 폴더로 나눠 둔다. 이 프로젝트는 `backend/`(FastAPI)와 `mobile/`(Expo)를 한 저장소에 둔다.
- **폴더는 같은 저장소에 있어도 프로그램은 완전히 분리되어 있다.** 언어(Python/TypeScript), 의존성(`uv.lock`/`package-lock.json`), 실행 명령, 배포 대상이 모두 따로다. 둘은 **HTTP API(JSON)로만** 대화한다. 앱이 백엔드 코드를 import하는 일은 없다.
- "분리"에는 두 층위가 있다.
  | 층위 | 이 프로젝트 |
  |---|---|
  | 실행·배포 분리(서로 다른 프로그램) | **분리함** — 앱은 폰에서, API는 서버에서 따로 실행 |
  | 저장소 분리(저장소 2개) | **안 함** — 한 저장소에서 이슈·PR·문서를 같이 관리 |

## 이 프로젝트 적용
- 결정: [ADR-0001](../architecture/adr/0001-fastapi-expo-monorepo.md) — FastAPI + Expo, 모노레포
- 한 저장소를 고른 이유
  - 1인 개발에서 **이슈 1개가 API와 화면을 함께 다루는 경우**가 많다(예: SRS-024 즐겨찾기 = API + ☆ 버튼). 저장소가 둘이면 PR도 둘로 쪼개져 추적이 어렵다.
  - 요구사항·아키텍처·일지 문서를 한곳에 둘 수 있다.
- 감수하는 점: CI에서 바뀐 폴더만 검사하도록 경로 필터를 둔다(SRS-003). 폴더별로 도구가 다르니 명령은 항상 `cd backend` / `cd mobile` 뒤에 실행한다.
- 저장소를 나누는 게 나아지는 시점: 팀이 생겨 백엔드·앱 담당과 권한이 갈릴 때, 배포 주기가 크게 달라질 때, 백엔드를 다른 클라이언트(웹 등)도 쓰게 될 때.

## 삽질 / 주의점
- 앱이 백엔드와 같은 저장소에 있다고 **API 주소를 코드에 박으면 안 된다.** `EXPO_PUBLIC_API_URL` 환경 변수로 주입한다(SRS-002). 또한 `EXPO_PUBLIC_` 값은 앱 번들에 그대로 들어가므로 비밀 값을 넣으면 안 된다.
- 폴더마다 `.gitignore` 대상이 다르다(`.venv/`, `node_modules/`) — 루트 `.gitignore`에서 함께 관리한다.
