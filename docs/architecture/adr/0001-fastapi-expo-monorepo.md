# ADR-0001 FastAPI 백엔드 + Expo 앱, 모노레포

- 상태: 제안
- 날짜: 2026-09-17
- 관련: PRD-001~005, SRS-001, SRS-002

## 맥락
- 서버가 출제 로직(혼동 단어 조합, 숙련도)과 유저별 데이터를 책임지고, 앱은 폰에서 푼다.
- 1인 개발이며 사용자는 주로 폰(Claude 앱 Remote Control, GitHub 모바일)에서 지시·확인한다.
- 학습 목표에 클린 아키텍처·DB 설계·보안이 있어, 백엔드는 계층을 직접 설계할 수 있는 가벼운 프레임워크가 좋다.

## 결정
- 백엔드: **FastAPI** (Python 3.12, 패키지 관리 **uv**). `backend/`
- 앱: **Expo**(React Native + TypeScript). `mobile/`. 실기기 확인은 Expo Go
- 한 저장소에 두 폴더(모노레포). 이슈·PR·추적표를 한곳에서 관리

## 대안
| 대안 | 선택하지 않은 이유 |
|---|---|
| React Native CLI (bare) | 네이티브 빌드 환경이 필요해 폰에서 원격으로 확인하기 어려움 |
| Django + DRF | 기본 구조가 정해져 있어 4계층을 직접 나누는 학습에 덜 맞음 |
| 백엔드·앱 저장소 분리 | 1인 개발에서 이슈·PR·문서가 흩어짐 |

## 결과
- 좋아지는 점: 이슈 1개로 API와 화면을 함께 추적, Expo Go로 바로 확인
- 감수하는 점: CI에서 경로별로 job을 나눠야 함(SRS-003), 두 언어의 도구를 모두 관리
- 재검토 조건: 앱스토어 배포나 네이티브 모듈이 필요해질 때(EAS Build 검토)
