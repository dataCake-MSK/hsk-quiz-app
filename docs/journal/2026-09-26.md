## 개발자 퀵 가이드
> 이날 결과로 이어진 진행사항만 압축.

### 핵심 진행사항
1. **DB 설명은 실물로**: 문서 설명 대신 `psql \d`와 실제 행을 뽑아 보여주면 이해가 빠르다 — 이를 규칙으로 고정
2. 용어는 **이 프로젝트의 실제 컬럼·제약**을 예로 들어 정리(일반론만 적으면 다시 안 보게 된다)

### 핵심 명령
```powershell
# .env의 접속 URL로 스키마와 샘플 데이터 확인 (드라이버 접두사만 제거)
$line = (Get-Content backend\.env | Where-Object { $_ -like "DATABASE_URL=*" })
$url = $line.Substring($line.IndexOf('=')+1).Replace('postgresql+psycopg://','postgresql://')
$env:PGCLIENTENCODING="UTF8"
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" $url -c "\d words"
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" $url -c "SELECT word_id, hanzi, pinyin, meaning_kr, hsk_level FROM words ORDER BY word_id LIMIT 6;"
```

### 핵심 코드·설정
`CLAUDE.md` — DB 변경 후 보고 규칙

```markdown
- **DB가 바뀌는 작업 뒤에는 데이터 모델링 설명을 함께 한다**(학습 목표 ①).
  1. 스키마: `psql "\d <테이블>"` 결과 그대로
  2. 실제 데이터 샘플: SELECT ... LIMIT 5~6
  3. 설계 이유: 왜 이 키·제약·인덱스인지, 대안은 무엇이었는지
  4. 새 용어는 뜻을 풀어 쓰고 docs/learning/db-terms.md에 추가
```
