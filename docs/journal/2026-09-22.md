## 막힌 점
- `uv run --env-file .env alembic upgrade head`가 `UnicodeDecodeError: 'cp949' codec can't decode byte 0xec`로 죽음 → 원인은 `alembic.ini`의 한글 주석. configparser가 **시스템 인코딩**으로 읽기 때문에 non-ASCII가 있으면 한국어 Windows에서 실패한다. ASCII로 바꿔 해결
- alembic 실행 로그의 한글이 콘솔에서 깨져 보임(`users ���̺� ����`). 동작에는 영향 없음 — 콘솔 코드페이지 문제

## 개발자 퀵 가이드
> 이날 결과로 이어진 진행사항만 압축.

### 핵심 진행사항
1. **로컬 DB 연결**: `.env`에 접속 정보를 넣고 `uv run --env-file .env`로 alembic·서버·테스트를 실행
2. **스키마 확인**: `psql "\d users"`로 제약(PK, UNIQUE, CHECK 2종)과 identity 기본값을 눈으로 확인
3. **되돌리기까지 확인**: `downgrade base` → `upgrade head`를 로컬에서도 한 번 돌려봄
4. **인코딩 문제 해결**: `alembic.ini`를 ASCII로 유지

### 핵심 명령
```bash
cd backend
uv run --env-file .env alembic upgrade head
uv run --env-file .env alembic downgrade base
uv run --env-file .env pytest -q          # DB 테스트 포함 16 passed
uv run --env-file .env fastapi dev app/main.py
curl http://127.0.0.1:8000/health          # {"status":"ok","db":"ok"}
```

```powershell
# psql로 테이블 구조 확인 (.env의 URL을 그대로 쓰되 드라이버 접두사만 제거)
$line = (Get-Content backend\.env | Where-Object { $_ -like "DATABASE_URL=*" })
$url = $line.Substring($line.IndexOf('=')+1).Replace('postgresql+psycopg://','postgresql://')
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" $url -c "\d users"
```

### 핵심 코드·설정
`backend/alembic.ini` — 접속 정보는 두지 않고, 파일 전체를 ASCII로 유지한다
```ini
# DB URL is NOT set here on purpose: migrations/env.py reads the DATABASE_URL
# environment variable instead, so no credentials are committed.
# Keep this file ASCII-only - configparser reads it with the system encoding
# (cp949 on Korean Windows) and non-ASCII text breaks `alembic` there.
# sqlalchemy.url =
```

`psql "\d users"` 결과 요약
```
user_id    bigint  not null  generated always as identity
email      varchar(320) not null   uq_users_email (UNIQUE)
role       varchar(10)  not null   default 'user'
created_at timestamptz  not null   default now()
CHECK ck_users_role            role IN ('user','admin')
CHECK ck_users_email_lowercase email = lower(email)
```
