### 핵심 명령
```bash
gh repo create <owner>/<repo> --public --source . --remote origin --push

gh api -X PATCH repos/<owner>/<repo> \
  -F security_and_analysis[secret_scanning][status]=enabled \
  -F security_and_analysis[secret_scanning_push_protection][status]=enabled
gh api -X PATCH repos/<owner>/<repo> \
  -F delete_branch_on_merge=true -F allow_squash_merge=false -F allow_rebase_merge=false

gh label create "type:feature" --color 1d76db --description "기능 구현" --force
gh api -X POST repos/<owner>/<repo>/milestones -f title="M0 기반"

gh issue list --state all --search "SRS-001 in:title" --json number   # 중복 확인
gh issue create --title "[SRS-001] ..." --body-file <파일> --label type:chore --milestone "M0 기반"

gh pr create --base main --head <브랜치> --title "..." --body-file <파일>
```

### 핵심 코드·설정
이슈 일괄 등록 스크립트의 핵심 (중복 확인 → 본문 파일 → `gh issue create`):
```js
const existing = execFileSync('gh', ['issue','list','--repo',REPO,'--state','all',
  '--search', `${i.id} in:title`, '--json','number'], { encoding: 'utf8' });
if (JSON.parse(existing).length) continue;          // 이미 있으면 건너뜀
fs.writeFileSync(file, body(i), 'utf8');
execFileSync('gh', ['issue','create','--repo',REPO,'--title',`[${i.id}] ${i.title}`,
  '--body-file', file, '--milestone', i.milestone, ...labelArgs]);
```

문서에 이슈 번호를 반영할 때 **Windows 체크아웃은 줄 끝이 CRLF**라서 `$` 앵커가 빗나간다. 정규식에 `\r?`를 넣는다.
```js
if (/· 이슈: -\r?$/.test(line)) line = line.replace(/· 이슈: -(\r?)$/, `· 이슈: #${n}$1`);
```
