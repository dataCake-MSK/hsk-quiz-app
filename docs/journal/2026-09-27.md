## 막힌 점
- Expo가 다시 8081 충돌 — 이번엔 **옆 프로젝트(`D_personal-api-app`)의 Expo**가 점유 중이었다(`Get-CimInstance Win32_Process`로 확인). 남의 프로세스는 끄지 않고 `--port 8082`로 띄움
- 실수로 **main에 직접 커밋**함(브랜치 전환 명령이 앞선 스크립트 실패로 되돌아간 상태였음). 브랜치 보호 덕분에 push는 막혔고, `git branch -f <브랜치> main` → `git reset --hard origin/main`으로 커밋을 브랜치로 옮겨 복구
- `expo lint`의 `react-hooks/set-state-in-effect`에 다시 걸림 — effect 안에서 `setState({kind:"loading"})`을 동기로 호출한 것이 원인. **로딩을 상태가 아니라 파생값으로** 바꿔 해결(결과에 요청 조건을 담고, 현재 조건과 다르면 로딩으로 간주)

### 핵심 진행사항
1. **아직 없는 테이블을 설명할 때는 임시 테이블로 시연**: `CREATE TEMP TABLE`로 만들고 실제 데이터와 조인하면 진짜 결과를 보여줄 수 있고 스키마는 그대로다
2. **effect에서 로딩 상태를 직접 세우지 않기**: 결과에 요청 조건을 함께 담아 `isLoading`을 계산하면 규칙 위반도 없고 경쟁 조건도 사라진다

type Result = { level: HskLevel; attempt: number; words?: Word[]; error?: string };

  const run = async () => {
